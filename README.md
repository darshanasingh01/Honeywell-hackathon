# Honeywell Hackathon — Synthetic Engine Simulator

A prototype for generating synthetic engine telemetry and sensor waveforms
for engine-condition analysis and machine-learning experimentation.

> **Important:** This project generates synthetic data. It is not validated
> against real engine measurements and must not be used for safety-critical
> diagnosis.

## Objectives

- Generate reproducible synthetic engine data.
- Simulate multiple operating and fault conditions.
- Export telemetry and waveform data as CSV.
- Inspect signal quality and sampling intervals.
- Explore frequency-domain and time-frequency representations using FFT
  and spectrogram analysis.
- Provide an interactive Streamlit interface for experimentation.

## Simulated Conditions

The simulator currently defines five conditions:

- `normal`
- `misfire`
- `knock`
- `valve_train_wear`
- `overheating`

These are simulation labels, not independent diagnostic predictions.

## Data Streams

### Telemetry

The telemetry output includes:

| Signal | Field | Unit |
|---|---|---|
| Engine speed | `engine_rpm` | RPM |
| Coolant temperature | `coolant_temp_c` | °C |
| Throttle position | `throttle_pct` | % |
| Engine load | `engine_load` | Simulator-defined scale |
| Short-term fuel trim | `stft_pct` | % |
| Long-term fuel trim | `ltft_pct` | % |
| Ignition timing | `ignition_timing_deg` | Degrees |
| Time | `timestamp_s` | Seconds |
| Condition label | `condition` | Categorical |

### Waveforms

The waveform output includes:

| Signal | Field | Unit |
|---|---|---|
| Microphone signal | `microphone_audio` | Arbitrary synthetic amplitude |
| Knock sensor | `knock_sensor` | Arbitrary synthetic amplitude |
| Crank position signal | `crank_pulse` | Synthetic pulse level |
| Accelerometer X | `accel_x` | Arbitrary synthetic amplitude |
| Accelerometer Y | `accel_y` | Arbitrary synthetic amplitude |
| Accelerometer Z | `accel_z` | Arbitrary synthetic amplitude |
| Time | `timestamp_s` | Seconds |
| Condition label | `condition` | Categorical |

The accelerometer axes represent one three-axis sensor category.
Some telemetry fields represent ECU-style values rather than independent
physical sensor measurements.

## Default Simulation Settings

- Duration: 10 seconds
- Telemetry sampling rate: 10 Hz
- Waveform sampling rate: 4,000 Hz
- Default random seed: 42

The dashboard allows the user to adjust simulation settings. Verify the
selected settings and simulator implementation when generating datasets.

## Run the Project

Activate your Python virtual environment, then install the dependencies
available in your project environment.

Run the test suite:

```bash
python -m pytest -q
```

Launch the dashboard:

```bash
streamlit run app.py
```

Open the local URL printed by Streamlit in your browser.

## Dashboard Features

- Condition and simulation-parameter controls
- Telemetry and waveform plots
- Signal-quality inspection
- CSV download
- FFT frequency-spectrum analysis
- Short-time Fourier transform (STFT) spectrogram visualization

## Signal Analysis

The FFT view helps inspect the frequency content of a selected signal.
The spectrogram shows how its frequency content varies over time.

Interpret results with the selected sample rate and the Nyquist limit in mind.
Synthetic peaks are generated by the simulator and should not be interpreted
as validated physical fault signatures.

## Reproducibility and Validation

Record the condition, duration, sampling rates, and random seed used for each
generated dataset. Use the same seed and settings when comparing runs.

Automated tests cover simulator behavior, signal quality, sampling validation,
and basic FFT/spectrogram properties. Passing tests verifies the tested
software behavior; it does not establish physical validity.

## Limitations

- Signals are synthetic and simplified.
- The simulator has not been validated against a real engine or dynamometer.
- The crank-position signal is a simplified model of a missing-tooth wheel.
- Signal amplitudes and units marked as arbitrary are not calibrated physical
  measurements.
- Fault classification requires separate validation using suitable real data.

## Dataset Generation and Validation

Generate the default synthetic datasets for all five conditions:

```bash
python -m simulator.engine_simulator
```

The generator writes telemetry and waveform CSV files to `data/raw/`.
The default settings are 10 seconds per condition, 10 Hz telemetry,
4,000 Hz waveform sampling, and random seed 42.

Validate the generated datasets and create summary metrics and diagnostic
plots:

```bash
python simulator/validate_signals.py
```

The validation report is written to `data/processed/signal_validation.csv`,
and diagnostic plots are written to `docs/plots/`.

Run the automated tests:

```bash
python -m pytest -q
```

**Data disclaimer:** These generated files are synthetic examples. They
must not be described as measured engine data or used as a substitute
for validation on real engine recordings.
