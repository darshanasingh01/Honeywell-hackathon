# Honeywell Hackathon — Synthetic Engine Simulator

A prototype for generating synthetic engine telemetry and sensor waveforms for engine-condition analysis and machine-learning experimentation.

> **Important:** This project generates synthetic data. It has not been validated against real engine measurements and must not be used for safety-critical diagnosis.

## Objectives

- Generate reproducible synthetic engine data.
- Simulate multiple operating and fault conditions.
- Export telemetry and waveform data as CSV.
- Inspect signal quality and sampling intervals.
- Explore frequency-domain and time-frequency representations using FFT and spectrogram analysis.
- Provide an interactive Streamlit interface for experimentation.

## Simulated Conditions

The simulator currently defines five conditions:

- `normal`
- `misfire`
- `knock`
- `valve_train_wear`
- `overheating`

These are simulation labels, not independent diagnostic predictions.

## Data Streams

### Telemetry

| Signal | Field | Unit |
|---|---|---|
| Engine speed | `engine_rpm` | RPM |
| Coolant temperature | `coolant_temp_c` | °C |
| Throttle position | `throttle_pct` | % |
| Engine load | `engine_load` | Simulator-defined scale |
| Short-term fuel trim | `stft_pct` | % |
| Long-term fuel trim | `ltft_pct` | % |
| Ignition timing | `ignition_timing_deg` | Degrees |
| Time | `timestamp_s` | Seconds |
| Condition label | `condition` | Categorical |

### Waveforms

| Signal | Field | Unit |
|---|---|---|
| Microphone signal | `microphone_audio` | Arbitrary synthetic amplitude |
| Knock sensor | `knock_sensor` | Arbitrary synthetic amplitude |
| Crank position signal | `crank_pulse` | Synthetic pulse level |
| Accelerometer X | `accel_x` | Arbitrary synthetic amplitude |
| Accelerometer Y | `accel_y` | Arbitrary synthetic amplitude |
| Accelerometer Z | `accel_z` | Arbitrary synthetic amplitude |
| Time | `timestamp_s` | Seconds |
| Condition label | `condition` | Categorical |

The accelerometer axes represent one three-axis sensor category. Some telemetry fields represent ECU-style values rather than independent physical sensor measurements.

## Default Simulation Settings

- Duration: 10 seconds
- Telemetry sampling rate: 10 Hz
- Waveform sampling rate: 4,000 Hz
- Default random seed: 42

The dashboard allows the user to adjust simulation settings. Verify the selected settings and simulator implementation when generating datasets.

## Prerequisites

- Python 3.14 (the development environment uses Python 3.14.6)
- Git
- Internet access to install dependencies

## Installation and Setup

### 1. Clone the repository

```bash
git clone https://github.com/darshanasingh01/Honeywell-hackathon.git
cd Honeywell-hackathon
```

To use the team's `sim` branch:

```bash
git switch sim
```

### 2. Create and activate a virtual environment

macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install dependencies

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

The `requirements.txt` file pins the dependency versions used by the project.

## Run the Project

### 1. Run the automated tests

```bash
python -m pytest -q
```

The tests cover simulator behavior, signal quality, sampling validation, CKP model behavior, and basic FFT/spectrogram properties.

### 2. Generate synthetic datasets

```bash
python -m simulator.engine_simulator
```

The generator writes telemetry and waveform CSV files for all five conditions to `data/raw/`.

Default generation settings:

- 10 seconds per condition
- 10 Hz telemetry sampling
- 4,000 Hz waveform sampling
- Random seed 42

### 3. Validate generated datasets

```bash
python simulator/validate_signals.py
```

The validation script checks the generated datasets and creates summary metrics and diagnostic plots.

Outputs:

- Validation report: `data/processed/signal_validation.csv`
- Diagnostic plots: `docs/plots/`

### 4. Launch the dashboard

```bash
streamlit run app.py
```

Open the local URL printed by Streamlit in your browser.

## Dashboard Features

- Condition and simulation-parameter controls
- Telemetry and waveform plots
- Signal-quality inspection
- CSV download
- FFT frequency-spectrum analysis
- Short-time Fourier transform (STFT) spectrogram visualization

## Signal Analysis

The FFT view helps inspect the frequency content of a selected signal. The spectrogram shows how its frequency content varies over time.

Interpret results with the selected sample rate and the Nyquist limit in mind. Synthetic peaks are generated by the simulator and must not be interpreted as validated physical fault signatures.

## Reproducibility and Validation

Record the condition, duration, sampling rates, and random seed used for each generated dataset. Use the same seed and settings when comparing runs.

Passing automated tests verifies the tested software behavior; it does not establish physical validity.

For reproducible comparisons, keep the simulation settings and software dependency versions consistent.

## Limitations

- Signals are synthetic and simplified.
- The simulator has not been validated against a real engine or dynamometer.
- The crank-position signal is a simplified model of a missing-tooth wheel.
- Signal amplitudes and units marked as arbitrary are not calibrated physical measurements.
- Fault classification requires separate validation using suitable real data.
- Synthetic data must not be presented as measured engine data.

## Team Integration

Coordinate data schemas, labels, sampling rates, and feature definitions with the feature-extraction and machine-learning contributors before combining outputs.

The simulator provides synthetic reference data for development and testing. It does not replace the actual dataset sourcing and machine-learning training owned by the relevant team members.
