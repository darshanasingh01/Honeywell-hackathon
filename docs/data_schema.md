# Synthetic Engine Dataset Schema

## Purpose and limitations

This dataset is generated by a Python prototype for a hackathon.
It is synthetic and illustrative; it is not measured engine data and
has not been validated against a real engine or diagnostic benchmark.

## Conditions

- `normal`
- `misfire`
- `knock`
- `valve_train_wear`
- `overheating`

Each recording represents one simulated condition. The `condition`
column is the target label for supervised experiments.

## Output files

For each condition, the simulator exports:

- `<condition>_telemetry.csv`
- `<condition>_waveform.csv`

Files are written to `data/raw/`.

## Telemetry schema

| Column | Unit / meaning | Nominal sampling rate |
|---|---|---:|
| `timestamp_s` | Seconds from recording start | 10 Hz |
| `engine_rpm` | Revolutions per minute | 10 Hz |
| `coolant_temp_c` | Degrees Celsius | 10 Hz |
| `throttle_pct` | Illustrative throttle percentage | 10 Hz |
| `engine_load` | Dimensionless simulated load, 0–1 | 10 Hz |
| `stft_pct` | Short-term fuel trim, percent-like value | 10 Hz |
| `ltft_pct` | Long-term fuel trim, percent-like value | 10 Hz |
| `condition` | Synthetic condition label | 10 Hz |

## Waveform schema

| Column | Unit / meaning | Nominal sampling rate |
|---|---|---:|
| `timestamp_s` | Seconds from recording start | 4,000 Hz |
| `microphone_audio` | Arbitrary synthetic amplitude | 4,000 Hz |
| `knock_sensor` | Arbitrary synthetic amplitude | 4,000 Hz |
| `crank_pulse` | Synthetic binary crank signal | 4,000 Hz |
| `condition` | Synthetic condition label | 4,000 Hz |

## Reproducibility

The simulator accepts a `seed` argument. Reusing the same seed and
parameters reproduces the same generated data.

## Integration notes

- Person B can process waveform windows and extract time/frequency features.
- Person C can evaluate classification and anomaly-detection pipelines.
- Person D can visualize sensor streams and model outputs.
- Keep recordings or windows from the same simulated run in the same
  train/validation/test partition to reduce data leakage.
- Treat simulation labels and signatures as hypotheses until validated
  against real recordings.
